# 既存ストレージへの資料移設・保管コピー（2026-10-02）

## 結果

Issue [#11](https://github.com/phni3j9a/sekirei-weight2/issues/11) で、既存の `/mnt/storage/NAS/sekirei-weight2` を資料と実験成果物の保管先にした。Mac mini上では `/dev/sdb1`（ext4）→ `/mnt/disk1` → mergerfs → `/mnt/storage` の構成で、空きは約5.8 TiB。新しい機材・サービスは導入していない。

資料原本113ファイルを移設し、main checkoutの `docs/pixiv_fanbox_yaneurao` をNASへの互換リンクに切り替えた。コピー前後のSHA-256を照合してからSSD上の旧実体を整理した。内蔵SSDの空きは23.376 GiBから30.239 GiBへ、実測で6.863 GiB増えた。ホスト上のほかの書き込みもあるため、この空き容量差は資料の論理サイズと厳密には一致しない。

Git/worktree、build、venv、実行用データ/重み、既存runはSSDに保持した。重み・教師pack・実験記録はNASにも保管コピーを置いた。CPU/RAM予算、toolchain lock、探索設定、モデル、正式比較条件は変更していない。

## コピーと照合

プロジェクトの保管ルートは `server` 所有・mode `0700`。runtime側の既存 `.prepare.lock` を排他的に取得し、関連処理がない状態でコピーした。既存の宛先は上書きせず、`rsync -a --no-owner --no-group --fsync` で作成したコピーについて、コピー前の原本、コピー後の原本、コピー先のファイル集合・サイズ・SHA-256とディレクトリ集合を照合した。

今回のsmokeと旧baseline再検証で作成した出力も、別の照合記録でNASに追加保管した（10ファイル、4,669,367 bytes）。新規の正式探索やfinal 5局の解析は行っていない。

## 実行環境の確認

- 資料の互換リンクが保管先と同じ実体を指すこと、SSD上の一時退避ディレクトリが残っていないことを確認した。
- `.gitignore` の資料パターンを末尾スラッシュなしにし、通常のディレクトリとシンボリックリンクの両方が除外されることを確認した。PR統合前のmainでは、ローカルの `.git/info/exclude` でも同じリンクを除外した。
- `python3 -B scripts/smoke.py` がv0.3.39 runtimeで成功した。smoke内部でバイナリ4本、教師重み、toolchain lockのハッシュを照合した。
- Sekireiは1,000,000 nodes、depth 13、exact 0 cp。教師は1,000,500 nodes、depth 20、手番視点 -64 cp lowerbound。双方のbestmoveは `2b8h+`、startup warningなし。shogiesaは1件のラベル生成とstrict validationに成功した。境界値を確定cpに変換していない。
- smoke summary SHA-256は `9b43d47a3db086114abb8172a8344b6998e8adce60fb57e68e62f6215ee76336`。これは環境疎通の確認であり、モデル改善や棋力を示す結果ではない。
- `git diff --check` に成功した。変更対象は文書とGit除外設定で、Pythonコードと比較設定に変更はない。

## 旧baselineの再検証

現行v0.3.39のcheckoutから旧 `development-baseline-20260916-v2` のreportを作る試行は、`run manifest toolchain lock does not match the current repository` で拒否された。固定版の不一致を検知する動作であり、データを修正して通してはいない。

当時の固定版 `ed76730`（PR #8統合時点）の一時的な専用worktreeからreportを実行し、正常完了した。headline MAEは `1,087.0461722818245 cp`、valid=true、formal=true、Teacher-Eに対する候補exact coverageは266/266で、公開済み結果と一致した。検証用worktreeは確認後に削除し、レポートはSSD runtimeとNASの非公開保管先に保持した。今後の旧baseline再検証にも、この版に対応するcheckoutを使う。

## 運用上の境界

NAS側のruntime記録は、ソース・バイナリ・venvを含む独立した実行環境ではない。既存runの絶対パスやfingerprintを維持するため、SSD上の元runtimeも保持している。資料原本の移設による容量回収と、実験成果物の保管コピーを区別する。

資料原本を移設した後、SSDの互換リンクは別のバックアップではない。今後のコピー・照合・復元は[環境文書](../ENVIRONMENT.md#内蔵ssdとnasの運用)の手順で手動実行する。定期同期・自動削除・マウント設定変更は行っていない。
