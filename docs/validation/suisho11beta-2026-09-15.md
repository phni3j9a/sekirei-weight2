# 水匠11β環境と生成済み教師の初期監査（2026-09-15）

## 結論

水匠11β（Suisho Concerto 202512）を主教師とするLinux/AVX2環境をMac mini上に構築できた。配布済みのβ・100万ノード `.pack` は固定V9.20環境と評価値の符号・尺度が近く、初期学習データとして採用する。ただし、元データに生成時エンジンの版・全option・評価値の境界種別がないため、完全に同じ教師環境から生成されたことまでは主張しない。

## 実機スモーク

固定版Sekirei、shogiesa、やねうら王V9.20をjobs=2でビルドした。build manifestのSHA-256は `09ac42b150394a85576c7e01b366d4aab2551f185e4a2e1a97c7f1909ac11a88`。

短いfixtureの同一局面で次を確認した。

- Sekirei: 1,000,002 nodes、exact 0 cp、0.568秒
- 水匠11β: 1,000,500 nodes、lowerbound -64 cp（手番視点）、2.320秒
- shogiesa: 1件抽出・1件ラベル・strict validate成功、重みSHA一致
- 評価関数の読込警告なし
- summary SHA-256: `5ae631f0737334cbf338b89c97d6735693ca4fed7a68d05225cadbaa0c4e55d0`

水匠側の最終値はlowerboundなので、確定評価値には変換していない。

## `.pack` 標本監査

cshogi 1.0.4 / NumPy 1.26.4を専用venvへ導入し、各固有packから「game ply 20以上で最初の有限評価値」を1件ずつ選んだ。監査器はHCP開始局面、game ply、Move16、符号付き評価値、終端記号をストリーム復号し、局面と開始後の指し手列を復元する。形式は[GenSfenの公開仕様](https://github.com/yaneurao/YaneuraOu-ScriptCollection/tree/main/GenSfen)と照合した。

固定V9.20を標本ごとに新規起動し、空のhashで100万ノード再解析した結果:

集計は10件中exact 6件、bound 4件、指し手一致6件。exactだけのMAEは3.167 cp、最大絶対誤差は11 cp、総探索時間は23.415秒だった。再解析結果のSHA-256は `3e45f5122d3b4af4412e4d58a618b66bb1131c30850567fd5892699490825e2a`。

928,395 / 951,450 nodesの2件は正常にbestmoveを返している。`go nodes` は到達義務ではなく上限なので、監査では下振れを失敗にせず実数を保存する。一方、上限超過は疎通確認と同じく2%までに制限した。

## 解釈と残事項

exact 6件の値が近く、0近傍だけでなく `-106 → -104` でも一致しているため、少なくとも符号反転、FV_SCALEの取り違え、別評価関数といった大きな不整合は見つからなかった。この範囲ではβ教師データを主軸にする判断は妥当。

ただし、次の理由から完全再現とは扱わない。

- 10局面だけの標本であり、4件は再解析がboundだった。
- `.pack` は元探索のboundを保存しないため、保存値が点推定だったか確認できない。
- 対象packには公開V9.20より前の日付のファイルがあり、元の開発版commitを特定できない。
- 元のGenSfenは1局の先後用プロセスを再利用するが、監査は局面ごとに新規プロセス・空hashである。
- 保存指し手の一致率は6/10で、探索状態または探索版の差が実際に観測された。

次はraw `.pack` を再配布・全量展開せず、ゲーム単位のtrain/development分割とSekirei学習器へのストリーム入力経路を作る。正式グラフ比較の棋譜はこの教師データと分離する。
